# 앱형 화면 전환과 돌봄 게임 설계

## 목적과 제약

긴 페이지를 스크롤하지 않고, 하나의 고정 프레임 안에서 기능별 화면을 전환한다. 백업 도구는 작게 고정하고 세 게임은 서로 다른 조작으로 재미를 높인다. 사용자는 이 화면 전환 방향을 승인했다. GitHub Pages 무료 배포, 로컬 서버 실행 금지, 기존 IndexedDB 기록·사진·경험치 보존을 유지한다. 실제 나무 인벤토리는 여전히 샘플이며 게임은 실제 생물 제거·가지치기 지침이 아니다.

## 화면 구성

- 앱 프레임은 동적 화면 높이(100dvh)를 기준으로 상단 제목, 현재 기능 화면, 고정 내비게이션으로 구성한다. 소개·이벤트·팀 정보는 별도 화면으로 이동하고 본문 아래에 계속 쌓지 않는다.
- 주요 화면은 나무 찾기, 내 나무, 돌봄 게임, 관찰장, 이벤트. 개인 나무 목록·관심·프로필·제보 등 기존 기능은 관찰장 안의 메뉴에서 접근한다. 기존 기능을 삭제하지 않는다.
- 데스크톱은 넓은 화면의 지도/목록 등 두 열 구성을 유지한다. 모바일에서는 위치 선택→후보 확인→배정처럼 단계별 화면으로 나눈다. 다음·이전으로 이동해도 입력값을 유지한다.
- 게임은 내 나무 아래에서 분리한 독립 화면이다. 내 나무의 게임 버튼과 튜토리얼 모두 이 화면으로 이동한다. 나무가 없으면 배정 안내를 제공한다.
- 기록 목록은 페이지 단위로 표시하고 관찰 작성은 단계별 입력으로 구성한다. 긴 상세 내용·백업 패널·모달은 내부 스크롤을 허용한다. 일반 문서 전체를 스크롤하는 구조는 없애되 작은 화면, 확대, 가상 키보드 때문에 내용이나 제출 버튼이 잘리지 않도록 내부 스크롤을 안전장치로 둔다.
- 화면 전환 시 제목에 포커스를 이동하고, 뒤로가기로 이전 화면을 볼 수 있게 URL 해시 기반 내비게이션을 사용한다. 유효하지 않은 해시는 나무 찾기로 처리한다. 공유 주소는 개인 화면 상태 없이 기본 사이트 주소를 사용한다.

## 고정 보관 도구

오른쪽 가장자리에 작은 ‘기록 보관함’ 버튼을 배치한다. 열면 브라우저 전용 저장 안내와 백업 내보내기·가져오기·사이트 주소 공유가 나타난다. 닫기/Escape와 포커스 복귀를 제공한다. 모바일에서 하단 메뉴와 겹치지 않도록 안전 여백을 둔다. 가져오기의 기존 덮어쓰기 확인과 오류·용량 검증은 보존한다. 데이터 삭제나 저장 형식 변경은 하지 않는다.

## 세 게임

게임별 시작→플레이→결과→보상 흐름과 기존 게임 ID를 유지한다. 최초 튜토리얼은 쉬운 속도, 일반 플레이는 보통 속도로 제공한다. 실패 시 경험치를 차감하지 않고 다시 시도할 수 있다.

1. 잎사귀 구조대: 30초 동안 다섯 대상을 잡는다. 기어가는 대상은 완만한 경로, 날아다니는 대상은 빠른 곡선 경로로 이동한다. 대상은 플레이 영역 경계를 벗어나지 않는다. 클릭/터치로 잡으면 사라지고 중복 점수는 없다. 조작 대상은 최소 44px이며 키보드로도 선택/잡기가 가능하다.
2. 가지 돌봄: 좌우로 왕복하는 바가 초록 성공 구간에 들어오면 ‘가지 돌보기’ 버튼이나 Space로 판정한다. 다섯 번 성공하면 완료한다. 빗나가면 해당 가지를 다시 도전하고 총 45초 안에 완료한다. 시각적 바 위치와 판정은 동일한 시간 기반 계산을 사용하며 키 반복 입력으로 연속 성공하지 못하게 한다.
3. 폭신폭신 흙 정원: 8열×12행 보드에 네 칸짜리 흙 블록이 떨어진다. 좌우 이동·회전·빠른 낙하로 가로줄 다섯 줄을 완성하면 성공한다. 채워진 줄은 사라지고 위 블록이 내려온다. 맨 위가 막히면 다시 도전한다. 다음 블록을 표시하며 키보드와 화면 버튼을 모두 제공한다. 특정 상용 게임의 이름·이미지·소리는 사용하지 않는다.

게임 중 화면을 떠나면 미완료 게임을 종료한다는 확인을 제공하고 보상 없이 정리한다. 탭이 숨겨지면 게임을 일시정지하며 프레임·타이머를 해제한다. 기존 보상 세션의 10분 제한을 넘으면 다시 시작하도록 안내한다. 동작 줄이기 설정에서는 장식 애니메이션을 줄이고 게임 속도를 낮출 수 있는 쉬운 모드를 제공한다.

## 상태와 보상

화면 상태와 게임 엔진 상태는 분리한다. 이동 경로, 타이밍 판정, 블록 이동/회전/충돌/줄 제거는 테스트 가능한 순수 함수로 구현한다. UI는 엔진의 실제 성공 결과가 발생했을 때만 기존 세션의 완료 목표를 기록하고 game-finish를 호출한다. 실패·중단은 보상을 요청하지 않는다. 기존 하루 게임별 25XP, 중복 보상 방지와 세션 만료 검증을 유지한다. 브라우저 전용 앱이므로 사용자 개발자 도구를 통한 조작까지 방지하는 서버 보안을 주장하지 않는다.

## 오류와 검증

저장 실패 시 성공 표시를 하지 않고 재시도 안내를 제공한다. 내비게이션 변경으로 진행 중 저장이 중복 실행되지 않게 한다. 기존 튜토리얼은 배정→작명→물주기→독립 게임 화면→이벤트로 다시 연결한다.

검증 항목: 화면/뒤로가기/해시 처리, 입력 유지, 기존 데이터 재접속, 보관 도구 접근성, 튜토리얼 연결, 게임 경계·충돌·회전·줄 제거·타이밍 경계·중복 입력·실패·보상 중복, 탭 전환과 타이머 정리. 타입·린트·전체 테스트·정적 빌드 후 GitHub Pages에 배포하고 분리된 브라우저 프로필에서 데스크톱/모바일 화면과 세 게임을 확인한다. 로컬 서버는 실행하지 않는다.

## 설계 검토

작은 화면의 ‘고정 프레임’을 내용 잘라내기로 구현하지 않는다. 일상 동작은 화면/단계 전환, 긴 상세와 접근성 확대 상황만 내부 스크롤을 허용한다. 저장 형식과 일일 보상 정책은 변경하지 않으며 기존 개인 기능으로 가는 경로를 유지한다. 구현 전 이 문서의 사용자 검토와 구현 계획 확정이 남아 있다.
