### 구현 및 검증 순서

1. `lib/local-store.ts`: IndexedDB 트랜잭션·사진·버전 백업 검증. `lib/local-api.ts`는 기존 화면이 요구하는 Response 형태의 garden/club/photos/trees 요청을 브라우저 내부에서 처리한다. 전역 fetch를 덮어쓰지 않는다. 테스트에서 메모리 저장 어댑터를 주입해 동일 로직을 검증한다.
2. `app/page.tsx`, `app/club.tsx`, `app/photo-upload.ts`: localFetch로 전환하고 개인 기록/체험 접수 문구 수정. 백업·복원 UI를 추가한다. Next Link/Image 대신 표준 요소로 정적 실행한다.
3. Vite React 진입점, GitHub Pages base 경로와 공식 Actions 배포 구성. 기존 Cloudflare 워크플로 제거. 기존 서버 소스는 역사적 참고로 남기되 빌드 제외, 배포依存 없음.
4. 테스트 먼저 작성하고 미구현 실패를 확인한 뒤 저장/보상/잘못된 복원/재접속/5그루 제한을 구현한다. 타입·린트·전체 테스트·정적 빌드 검증 후 공개 Pages에 배포한다.
5. 실제 온라인 HTTP/정적 자산 검사, 브라우저 기능 테스트(사용자 명시 요청). 로컬 서버는 모든 단계에서 금지. 실패한 흐름은 회귀 테스트 후 수정하고 실제 배포 URL과 한계를 보고한다.

검토 초점: 저장 차단 및 용량 오류, 백업 악성/손상 입력의 원본 보존, 여러 탭 중복 보상, 사진 참조 유효성, 프로젝트 경로에서 새로고침과 링크.

검토 수정: 실패한 관찰 저장의 임시 사진 누적을 실패 시 정리하도록 수정(첨부된 사진 보호). 한글 백업 문자 수/UTF8 바이트 수 불일치 수정; 저장 전 100MiB 백업 크기 보장과 초과 시 트랜잭션 롤백. 실제 IndexedDB 어댑터의 다중 연결 중복 보상·재접속·실패 롤백 검증 추가.

온라인 기능 검증: 나무 배정→작명10XP→물10XP→거름15XP→미니게임25XP, 재접속60XP 유지, 사진 관찰 저장, 백업 내보내기 실행. 서버 API 네트워크 요청0. 자세한 범위와 제한은 docs/test-report-2026-09-30.md.

## 설계
실제 나무에 관심과 기록을 쌓는 서울 중심 참여 서비스. 위치를 직접 선택하거나 GPS로 지정하고 반경 안의 거리순 상위 10개에서 균등 추첨한다. 후보가 10개 미만이면 실제 후보 수를 표시한다. 현재 실제 나무 인벤토리가 제공되지 않아 시연 좌표는 샘플로 명시한다. 원본 콘텐츠 조사 결과는 별도 문서에 보존한다.

화면: 짙은 숲색과 크림색, 손그림 느낌의 자체 SVG 나무, 지도·나무 목록·가상 정원·활동 일지·이벤트. 원본 사진은 출처와 재사용 조건이 확인된 경우에만 채택하며 원본과 공식 제휴로 오해하지 않도록 출처 표기.

데이터: D1에 익명 방문자 쿠키별 나무 선택, 행동, 기록, 이벤트 신청 저장. 서버에서 거리 계산, 배정, 성장, 일일 행동 제한과 이벤트 조건 검증. GPS 방문 인증은 좌표 정확도와 거리 제한을 적용하며 위변조 방지 인증을 보장하지 않음. 샘플 나무는 실제 방문 인증으로 인정하지 않고 명확한 체험 기록 제공.

보호: 물·거름은 가상 행동. 실물 이름표는 일정 횟수의 실제 방문과 관리주체 허가 후 가능하며 비접촉 방식 및 제거일 필수. 체험판은 실제 이벤트 신청 대신 관심 등록만 가능.

검증: 거리와 추첨 후보, 반경 경계, 입력 검증, 성장 계산 테스트; 타입 검사·린트·배포 빌드; HTTP/API 시나리오. 실제 데이터와 승인된 이벤트가 없는 상태를 숨기지 않는다.
